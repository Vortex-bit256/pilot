# ADR 0001: Событийное ядро агента (event-driven core)

- Статус: принято, реализовано в фазе 1
- Дата: 2026-08-06

## Контекст

Планируется четыре клиента: CLI, VS Code extension, desktop (Win/macOS) и web.
Исходный `Agent.run(): Promise<string>` возвращал только финальный ответ:
невозможно показать прогресс, стриминг, вызовы инструментов или запросить
подтверждение у пользователя. UI был жёстко связан с ядром, а ядро писало
debug-логи в stderr само.

## Решение

`Agent.run()` — async-генератор: `AsyncGenerator<AgentEvent, string>`.
События (`text`, `tool_call`, `tool_result`, `usage`, `done`) описаны в
`src/protocol/events.ts` и являются контрактом для всех клиентов.
Ядро не пишет в stdout/stderr вообще; рендеринг — забота клиента
(в CLI это `cli/render.ts`, debug-режим — эталонный подписчик на события).
Фатальные ошибки бросаются исключением; транспорт (фаза 4) сериализует их.

## Последствия

**Плюсы:** любой UI работает без изменений ядра; стриминг, permissions и
отмена ложатся на тот же поток событий; headless server (фаза 4) — чистая
сериализация протокола.

**Минусы:** потребление чуть сложнее (`while (!step.done)` вместо одного
`await`); появляется отдельный пакет типов, который надо держать стабильным.

## Альтернативы

- **Callback-API (`onEvent(cb)`)** — отвергнуто: генератор бесплатно даёт
  backpressure, порядок и возвращаемое значение.
- **EventEmitter** — отвергнуто: нет возвращаемого значения, слабее типизация
  потока, ручное управление подписками.
- **Оставить `Promise<string>` и добавить события позже** — отвергнуто:
  единственное решение, которое дорого вводить задним числом, т.к. меняет
  сигнатуру главного метода ядра и всех клиентов.
